## B. Design holes — proposals (learner confirmed alignment same day → implemented; per-item status below)

> **Status legend:** ✅ implemented 2026-07-05 · ⏳ open (needs learner input or a future session).

### B1. ✅ Live logging has no enforcement — it already failed once (highest priority)
The 2026-07-03 miss proves the rule "update progress-log the moment things happen" is aspiration,
not mechanism: that session updated *three other* files but never the one that drives resume.
**Proposal (pick any/all):**
- **(a) Artifact-pairing rule** in CLAUDE.md: any write to a subject's files (lesson saved,
  profile/preference updated, KB touched) **must be preceded by** a progress-log line recording the
  event that caused it. The log is written *first*, the artifact second — position updates can then
  never lag the artifacts.
- **(b) A harness Stop/SessionEnd hook** (via `.claude/settings.json`) that reminds/blocks on
  "progress-log untouched this session while subject files changed." Strongest guarantee; needs the
  update-config step — say the word and I'll wire it.
- **(c) Session-start integrity check:** step 2 of the protocol also compares the resume block's
  date against the newest artifact date in the subject tree; a mismatch = a missed session →
  reconstruct-from-artifacts (exactly what this audit did) before teaching.
My recommendation: (a) + (c) in the contract now; (b) as belt-and-braces.

### B2. ✅ The teaching gate is undefined for verilog & python (pre-two-stage subjects)
The gate ("only at `stage-2✓`") is defined in a **sem-3-scoped file** but applied globally by
CLAUDE.md. Verilog and python predate the vocabulary: no stage status exists for them, no §0
surplus exit test is on record — yet verilog orientation has already been taught. Their
"exhaustive deep pass" is *probably* stage-2-equivalent, but nothing certifies it.
**Proposal:** (1) promote the status vocabulary + gate definition from
`subjects/sem-3/research-engine/two-stage-depth.md` to an engine-level home (root or
`subjects/README.md`), leaving sem-3 to reference it; (2) run the §0 surplus exit test on the
verilog and python KBs once and stamp an explicit `stage-2✓-equivalent` line in their 00-maps.
Cheap, closes a gate loophole.

### B3. ✅ TEACH-READY sem-3 subjects are missing the files the session protocol loads
Session-start step 2 loads `learner-profile.md` + `progress-log.md`; `subjects/README` also
requires `curriculum.md`. **03-electronic-devices-1 and 04-digital-electronics (both TEACH-READY)
have none of the three** (01-statistics has all). First activation would improvise them mid-boot.
**Proposal:** scaffolding is part of reaching `stage-2✓` — generate curriculum (from 00-map +
exam-map) + empty profile/log the moment a subject passes the gate. I can scaffold 03/04 on your
go (curriculum derivation is content work, so I didn't do it unasked).

### B4. ✅(minimal) Spaced review doesn't cross subjects
Each subject has its own queue; the protocol reviews only the *active* subject's due items. With
5+ subjects, items due in stats will silently rot while you do verilog — the exact anti-spacing
failure the engine exists to prevent. (All queues are empty today, so nothing is lost *yet*.)
I added a minimal sweep line to CLAUDE.md step 4 (flagged here because it edges past "mechanical"
— revert if you'd rather design it differently).
**Fuller proposal:** a root `review-dashboard.md` (or a tiny tool) aggregating every subject's
due-today items at session start; becomes important the week the first queues fill.

### B5. ✅(structure) / ⏳(dates) No exam calendar → spacing can't target the MTE/ETE
Nothing anywhere records *when* the exams are; expanding-interval scheduling and exam-taper
(shrink intervals approaching the date) both need it. **Proposal:** an `exam-dates` field in each
sem-3 `course-info.md` + a queue column; scheduling rule: normal expanding intervals, tightening
into the last pre-exam week (evidence-aligned — it's spacing, not cramming, when the material was
learned earlier).

### B6. ✅ MOT gate exception contradicts the contract as written
The queue records a learner-decided, subject-scoped exception (stage-1✓ = teaching gate for MOT,
2026-06-26), but CLAUDE.md states the gate as absolute ("never teach below stage-2✓ — hard").
A future session reading only the contract would refuse to teach MOT. **Proposal:** one line in
the CLAUDE.md gate paragraph: "subject-scoped exceptions may be learner-logged in the research
queue (currently: MOT, 2026-06-26)."

### B7. ✅ Mermaid `theme: 'dark'` on white figure cards (lesson polish)
`render_lesson.py` initializes Mermaid with the dark theme, but figures sit on **white** cards.
Flowchart nodes survive (dark boxes, light text), but dark-theme **edges/labels are light-grey on
white** → low contrast, and mindmaps fare worse. Plausibly part of why the 2026-07-03 map read as
messy. **Proposal:** switch to `theme: 'neutral'` (built for light backgrounds) and re-render the
verilog orientation lesson from its build script as the visual A/B. One-line change; I left it
un-flipped because it changes the look of an artifact you've already seen.

### B8. ✅ Root-cause pattern worth adopting as a rule
Three of the holes above (A2, A6, B6) are the same failure: **live state written into static
docs**, which then rot. The system already has the right discipline for *logs* ("never reconstruct
from memory"); the missing twin rule is **"static docs never carry live state — they point to the
state files."** Proposal: add that one sentence to CLAUDE.md's source-of-truth block; it prevents
the whole class.
